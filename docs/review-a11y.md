## 1. 総評

構造とキーボードの土台（`say()`/`#live`、`aria-label`、`:focus-visible`、reduced-motion、Esc、`visibility:hidden` による畳み込み）は真面目に作ってある。ところがその上に **`render()` が DOM を毎回作り直す**設計が乗っていて、押した瞬間にフォーカスが `body` へ落ち、レールのスクロールが先頭へ戻る。実測で、キーボードだけで「for を置く→数を入れる→print→並べ替え→削除→設定で並び替え」を通すのに **440 キー**かかった（設計書が誇る「10タップ」の相手ではない）。
「たな」へブロックを預ける操作は **ドラッグにしか経路が無い**（`SHELF.push` はソース中 1372行目の `dragEnd` 内 1箇所のみ）。BLOCKS.md と CLAUDE.md が二度にわたり「2.5.7 の単一ポインタ代替は満たしている」と書いているが、**満たしていない**。
色は、分類6色の設計そのものは妥当（実測値も設計書の表と一致した）。問題は色ではなく **`opacity`** で、起動直後は 75札中 55札が `.34` に沈み、実効 1.61〜2.09:1 になる。これらは `disabled` ではなく押せるボタンなので 1.4.3 の適用外にならない。
選択行の塗りは **1.28:1**（実画素）、字下げ棒は深さ3で **1.26:1**、視覚上の段差は **1レベルあたり 8px**。入れ子の深さは見えていない。
一方で、フォーカスが sticky 見出しに隠れる事故（2.4.11）は **95停留点を全走査して 0件**、ページ横スクロールは 320px でも **0**、reduced-motion で全アニメが止まることも実測で確認した。ここは通っている。

#### A-02 / 2.4.3 フォーカス順序（A）— `render()` のたびにフォーカスが `body` へ落ちる

- **該当**: `render()`（768-779、`c.innerHTML=''`）、`renderRail()`（1026-1028、`rail.innerHTML=''`）、`ordPaint()`（1546-1548、`L.innerHTML=''`）
- **実測**（`m4.js` / `m22.js`）:

  | 操作 | 操作前のフォーカス | 操作後のフォーカス |
  |---|---|---|
  | レール札 `print` で Enter | `button.rb.st「print」` | **BODY** |
  | 面の行で Enter（選択） | `div.row「深さ0 print()」` | **BODY** |
  | 設定シートの「↑」で Enter | `button「「だす・いれる」を上へ」` | **BODY** |

- **直す方向**: `render()` の直前に `document.activeElement` の識別子（レール札は `r.id`、行は配列位置）を控え、描画後に同じ要素へ `focus({preventScroll:true})` する。`toggleSec` の書き方をそのまま横展開すればよい。

#### A-05 / 2.5.2 ポインタのキャンセル（A）— `pointercancel` が削除を確定させる／取り消しが無い

- **該当**: `beginDrag()`（1298-1306、`window.addEventListener('pointercancel',dragEnd,{once:true})`）、`dragEnd()`（1351-1368）
- **実測**（`m19.js`）:
  - `.grip` に `pointerdown` を1回送っただけで、`up` を待たずに **DRAG 開始・killzone 表示・ゴースト生成**（`{"dragStarted":true,"killzone":true,"ghost":true}`）。
  - その状態で面の外の座標（5,5）に `pointercancel` を送ると、`PROG` が **1→0**、トーストに「消しました」。つまり**利用者が離していないのにブロックが消える**。
  - 取り消し手段はソース中に存在しない（`undo` / `Ctrl+Z` / 「元に戻す」いずれも 0件）。
  - `beforeunload` ガードも無い（`typeof window.onbeforeunload === 'object'`(null)、ソース中に `beforeunload` の文字列 0件）。組んだ木は localStorage に保存されない（リロード後 `PROG.length===0` を実測）。
- **誰が困るか**: 手が震える人、ペン／タッチで OS のジェスチャに横取りされた人、Android の戻るジェスチャや iOS の Slide Over に触れた人。10分かけて組んだ木が黙って消える。このアプリの目的が「10分打ってエラーで詰む体験を無くす」ことなのに、その事故を別の形で再生産している。
- **直す方向**: (1) `pointercancel` は `dragEnd` ではなく「元の位置へ戻す中止」に繋ぐ。(2) 削除は最低限 1手の取り消し（直前の `PROG` のスナップショットを1段だけ持つ）を付ける。(3) `PROG` を localStorage に自動保存する（BLOCKS.md で「保存する」と決めた通り。CLAUDE.md では未実装扱いのまま）。

#### A-11 / 1.3.1（A）— 「いま押したらここに入る」状態（`.slot.act`）が DOM に無い

- **該当**: `slotEl()`（835-846）、`.slot.act`（CSS 216行）
- **実測**（`m7.js`）: 差し先になっているスロットは `{role:"button", aria-label:"式 kansu", aria-pressed:null, aria-current:null, class:"slot act"}`。`aria-label` は**活性でないスロットと同一**。

- **直す方向**: `.slot.act` に `aria-current="true"` を付ける。`.railnow` は `aria-live="polite"` にするか、`say()` を差し先の変化点すべてに置く。

#### B-01 【最大の実害】レールのスクロールが毎回先頭へ戻る

- **該当**: `renderRail()`（1027行 `rail.innerHTML=''`）、`render()` から毎回呼ばれる

- 直す方向: `focusin` で引き戻す先を「シート内の最初」固定にせず、`Tab`/`Shift+Tab` の方向を見て先頭／末尾へ振り分ける（標準的なフォーカストラップ実装）。
