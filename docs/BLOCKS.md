# BLOCKS.md — ブロックで組んでから書く（pyblock 設計）

> 第5のアプリ `pyblock.html`。**骨組みは実装済み**（組む → 実行 → 写経 → 判定 まで通る）。
> 読みやすい版: https://claude.ai/artifact/2NRJqxpmTcXodPst5b88hV

## 解こうとしている問題

スマホで Python を打つと、**10分かけて書いたコードがエラーになる**。原因が「構造を間違えた」のか
「コロンを忘れた」のか切り分けられない。何が悪かったのか学べないまま疲れだけが残る。

初学者が詰むのは **構造**（何をどう繰り返すか）と **記法**（Python の文字の並べ方）を
**同時に**やらされるから。ブロックで先に構造を確定させれば、残る不確実性は**記法だけ**になる。

## 4つの段

1. **ブロックで組む** — タップだけ。キーボードを出さない
2. **実行して動く** — 成功体験1「構造は正しい」
3. **ブロックを見ながら Python で打つ** — **生成された Python は見せない**
4. **出力がブロック版と一致** — 成功体験2「書けた」

**③で Python を見せてはいけない。** 見せると「文字の書き写し」になり、確定させた構造が使われず
成功体験も薄い。見せるのは**形**だけ:「この形を Python で書くとどう書く？」——確定しているのは構造、
思い出すのは記法。詰まったとき用に「答えを見る」は用意する。採点は**ブロック版の出力との一致**
（記述モードと同じ `PyRun.norm` 比較）。

## 速さが生命線

この企画が成立するかは①が本当に速いかだけで決まる。`for i in range(4):` の中に `if` と `print`:

| | 数 | キーボード |
|---|---|---|
| ブロック | **10タップ**（for 1 + 数字 1 + if 1 + 条件チップ 5 + print 1 + 式チップ 1） | **0回** |
| 手打ち | 41文字＋インデント＋記号 | 必須 |

**最初に検証すべきはここ。** 見た目より先に操作感を出す。

**実測（2026-09-17）**: 数は「123 数を書く」でブロックに直接書き込む（キーパッド）。
`1` の札を探す必要が無くなった。任意の数・小数・負数も入る。

**実測（2026-09-15・骨組み）**: `def tasu(a,b) / return a+b / print(tasu(2,3))` が
**14タップ＋関数名の入力1回**。手打ちなら56文字。360px で横スクロールなし。
最初は16タップだったが、`def` の外へ出すのに「行を選ぶ→⇤→スロット」で3タップ使っていたため、
レールに **「⇤ 外へ」**（挿入点を親の次へ出す）を足して14に減らした。

## 2層に分ける

| 層 | 組むもの | やり方 |
|---|---|---|
| **文** | for / if / while / print / 代入 | 新規のブロック（入れ子・タップで挿入） |
| **式** | `i % len(kansu)` / `kansu > 3` | **既存の組み立てドリルのチップ方式を流用** |

式まで入れ子ブロックにすると複雑さが倍になる。式を組む UI は46問のドリルで**もう完成している**。
新規に作るのは「文を縦に積む部分」だけ。

## ブロックカタログ（第1版・14種）

範囲は**辞書がカバーする範囲に揃える**。

| id | ブロックの表示 | 生成される Python |
|---|---|---|
| `assign` | ［変数］に［式］を入れる | `kansu = 5` |
| `addassign` | ［変数］に［式］を足し込む | `kansu += 1` |
| `input` | ［変数］に入力を1行読む | `kansu = input()` |
| `input_int` | ［変数］に入力を数として読む | `kansu = int(input())` |
| `print` | ［式］を表示 | `print(kansu)` |
| `print_end` | ［式］を改行せず表示 | `print(kansu, end='')` |
| `for_range` | ［変数］を0から［数］回くりかえす | `for i in range(4):` |
| `for_in` | ［式］から［変数］を1つずつ | `for x in kansu:` |
| `while` | ［条件］の間くりかえす | `while kansu > 0:` |
| `if` | もし［条件］なら | `if kansu % 2 == 0:` |
| `else` | そうでなければ | `else:` |
| `append` | ［変数］に［式］を足す | `kansu += [x]` |
| `break` | ぬける | `break` |
| `continue` | 次へ飛ばす | `continue` |
| `def` | ［名前］（［引数］）という処理をつくる | `def tasu(a, b):` |
| `return` | ［式］を返す | `return a + b` |
| `call` | ［名前］を呼ぶ | `tasu(2, 3)` |
| `elif` | そうでなくて［条件］なら | `elif kansu > 0:` |
| `pass` | なにもしない | `pass` |
| `raw` | じゆう（1行そのまま書く） | 書いたとおり |

**関数は第1版から入れる。** 名前を付けられることが、自由に作るサンドボックスの手応えを決めるため。

**第1版では入れない**: import / 辞書 / スライス / try / lambda / 内包表記

## データ構造

```js
[
 {t:'def', name:'tasu', args:['a','b'], body:[
    {t:'return', e:['a','+','b']}
 ]},
 {t:'print', e:['tasu','(','2',',','3',')']},
 {t:'assign', v:'kansu', e:['5']},
 {t:'for_range', v:'i', e:['4'], body:[
    {t:'if', e:['i','%','2','==','0'], body:[
       {t:'print', e:['i']}
    ], orelse:[
       {t:'print', e:["'-'"]}
    ]}
 ]}
]
```

- `v` = 変数名スロット（固定の小集合から選ぶ）
- `e` = 式スロット。**トークン配列**＝既存ドリルと同じ形なので `joinCode()` がそのまま使える
- `body` / `orelse` = 子ブロックの配列
- `name` = 関数名。**ここだけキーボードを使う**（`def` のみ）
- `args` = 引数名の配列。固定の小集合から選ぶ（`def` のみ）

**コード生成**: 木を歩いて1文1行。C字は `:` で終えて `body` を深さ+1 で再帰。
インデントはスペース4つ固定。式の文字列化は既存の `joinCode(e)`。

## 操作モデル（タップ＋ドラッグ併用・レールは左）

**2026-09-17 変更**: ドラッグ&ドロップを足した（iPad 対応に伴い）。
ただし**タップ挿入は残す**。速さの生命線であることに加え、**WCAG 2.2 の 2.5.7（ドラッグ操作）は
ドラッグに単一ポインタの代替を必須にしている**ため、タップとキーボード操作は仕様上も必要。

- **レールの札をドラッグ** → 置きたい場所へ。**判定は「レールの外へ出たか」**。
  縦移動で判定してはいけない（レールは縦スクロールする。下部の札を面の上部へ運ぶと
  縦移動の方が大きくなり、実測 dx=182 / dy=367 で横優先の判定は成立しなかった）。
- **行のグリップ（⠿）をドラッグ** → 並べ替え・入れ子への出し入れ。幅は 24px（WCAG 2.5.8 最小）。
- **面の外へ出すと削除**。ドラッグ中は画面下に「はなすと消えます」を出し、ゴーストを赤にする。
- **たな** — 使わないブロックの置き場。ドラッグで預け、タップで挿入点へ戻す。
- ドラッグ直後の click は 400ms 無視する（レール札の tap と二重挿入になるため）。

## レールの見た目＝macOS のソースリスト（2026-09-17）

参照: macOS の Sidebar / Source List（`NSOutlineView` のグループ項目、`NSSplitViewController.toggleSidebar(_:)`）。
**踏襲した所**と**踏襲しなかった所**を分けて残す。後から「なぜ真似ていないのか」で迷わないため。

踏襲した:

- **行は左揃えの平たい列**。影も枠も無い。印（15px）＋ラベルの2カラムで、
  `.tx` の左端は全行そろえる（実測 48px の1列）。
- **グループ見出しは行き先ではない**。`pointer-events:none` で押せない。
  `isGroupItem:` が返す非選択の見出しと同じ扱い。
- **見出しは sticky**。ただし節ごとに `.rsec` の箱に入れる。
  箱に入れないと sticky の含みブロックがレール全体になり、**通り過ぎた見出しが上に積み上がる**。
  箱に入れた今は常に1枚だけ貼り付く。
- **畳めるサイドバー**。切替は分割長方形のアイコン（`toggleSidebar(_:)` の標準アイコン）。
  畳んだら `--rail-w:0` に加えて padding も 0・`visibility:hidden` にする。
  opacity だけだと細い帯が残り、**Tab が見えないレールの中を巡る**。

踏襲しなかった:

- **選択の塗り**。ソースリストの選択は「いま居る行き先」を示す。
  レールは行き先ではなく道具箱で、押すと挿入されて終わり、選択は残らない。
  塗りを残すと嘘になるので付けない。押した瞬間だけ `:active` で紫に沈む。
- **半透明（`NSVisualEffectView`）**。`backdrop-filter` は使わない。
  tango で記録済みの通り、親の filter 変更のたび再計算されて古い GPU のスクロールを殺す。
  代わりに**明度差だけ**で材質を分ける（レール `hsl(276,16%,11%)` / 面 `hsl(276,15%,8%)`）。
- **行ごとに違うアイコン**。印は**分類ごとに1種**。
  `+` `<` `[` `'` のように**札そのものが記号の行には印を出さない**（同じ形が2つ並んで読みにくい）。
  桁だけ空けて列は保つ。

足したもの:

- **`.railnow`（レールの先頭に貼り付く1行）** — レールが持つ唯一の本物の状態＝
  **「いま押したらどこに入るか」**。`print の式` / `def の引数` / `2行目に文`。
  見出しの sticky 位置はこの行の**実測高さ**を `--now-h` に入れて合わせる（折り返しても潜らない）。
- **入らない節は薄く**（`.off`, opacity .34）。式の差し先が無いときに `+` を押すと
  トーストが出るだけだったのを、**押す前に分かる**ようにした。
  押せなくはしない——押せば理由がトーストで出る方が学べる。

## 旧: 操作モデル（ドラッグは使わない・レールは左）

スマホで掴んで運ぶ操作は遅く、360px では特に苦しい。**挿入点が常に1つあり、
レールをタップするとそこに入る。**

**レールは左が既定**（作者が左利き。拾う手が左、読む面が右）。
**左右は設定で入れ替えられる**——利き手が変われば親指圏も変わるため。
レールは**縦に弾いて（スワイプして）探す**。分類の見出しが挟まる。つまみを引くと畳めて面を全幅にできる。
レールの札は**短い名前**（`print` `for` `def`）で、**意味はホームで引く**。

- レールのブロックをタップ → 挿入点に入り、挿入点はその次へ
- C字ブロックを入れたら挿入点は**自動で中に入る**（for を置いた次は中身を書くのが普通）
- ブロックをタップ → 選択。↑ ↓ ⇤ ⇥ 🗑 が出る（移動・字下げ・削除）
- 「外に出る」で挿入点を親の次へ
- 自分で作った関数は**レールの「じぶん」欄に並ぶ**。以後タップで呼べる

**キーボードを出さない工夫**
- 変数名: `kansu` `kansu1` `kansu2` `i` `n` `x` の固定パレット（約束4 と一致）
- 数: テンキー＋よく使う値（0 1 2 3 5 10 100）
- 文字列: プリセット（`''` `' '` `'-'` `'OK'`）＋必要なら短い入力
- 演算子: 既存のチップ
- **関数名だけは打つ** — 名前を付けるのは関数ごとに1回で、しかもそれ自体が学習内容。
  トークン1つずつ打つのとは性質が違う

## 画面の分担

説明と作業を混ぜない。**組み立て面は隔離する。**

- **ホーム＝ブロックの辞書**。どのブロックが何をするかを引く場所。
  **辞書・原子辞書・エラー辞書と同じデータ形**にすれば、各ブロックの例を `verify.py` で実行照合できる。
  自分が作ったものの一覧と、任意のお題もここ。
- **組み立て＝作業場**。説明は置かない。面とレールと実行だけ。
  **何を作るかは自由**——サンドボックス。お題は欲しい人だけが取りに行く。

## サンドボックスと保存

- **自由に作る**。何を作るかは決めない。組んで、動かして、気が済んだら残す。
  作ったものは **localStorage に名前を付けて保存**し、ホームに一覧が出る。
- **お題は任意**。「この出力になるように組め」は欲しい人だけが取りに行く。強制しない。
  既存46問と同じ題材を流用できる。

## verify.py との関係

サンドボックスは自由なので検証対象が無い。**検証面は「ホームのブロック辞書」が担う**——
各ブロックの例プログラムを、既存の3辞書と同じ形で実行照合する。

素直にやると**コード生成器が JS と Python の2つ**必要になり、既知の負債である二重管理がもう1件増える。

**回避策**: データに `blocks` と**生成結果 `code`** と `out` を持たせる。`verify.py` は `code` を
実行して `out` と一致するかだけを見る（既存の検査と同じ形）。
**JS 側の生成器が同じ `code` を吐くかは、アプリ起動時に1回自己テストする。** ズレたら即わかる。

## 障壁

**設計で潰したもの**
- モバイルのドラッグ&ドロップ → 廃止。最大の障壁が消えた
- 式の複雑さ → 既存チップ再利用で実装量が半減
- 横スクロール → 段差を色帯にして解消
- 生成器の二重管理 → データに生成結果＋起動時自己テスト
- 実行基盤 → `PyRun`（Worker・逐次出力・中断）がそのまま使える

**残るもの**
- パレットの物量（14ブロック＋スロット）で画面が窮屈 → タブで分ける
- 式チップの文脈依存（条件用 vs 算術用）→ 最初は全部出す
- 間違った構造も組めてしまう → 実行すればエラーが出る。それは学びなので許容
- **面の幅** — 360px からレール96px を引くと面は約250px。長い式は横スクロールか省略になる。
  **試作で最初に見るべき点**
- **関数のスコープ** — 引数と外の変数の区別は初学者の壁。第1版は引数を固定小集合にして踏み込まない
- 規模。これまでで最大 → 段階的に出す

## 置き場所

`pydrill.html` / `pydrill-pro.html` の中には**入れない**。2枚はすでに120KB超で中身が重複しており、
大きな機能を足すと同じものを2回書くことになる（検証349件の面にも影響）。

`pyplay.html` と同じく**独立した1枚 `pyblock.html`** で作り、育ってから合流を判断する。
ブロックを組むところまでは純粋な JS なので**オフラインで動く**。通信が要るのは実行のときだけ
——約束2 の構造と一致する。

## 決まったこと / 残り

決まった: **サンドボックスにする** ／ **お題は任意** ／ **保存する**（localStorage・ホームに一覧）
／ **関数を入れる**（名前を付けられる） ／ **レールは左**（設定で入れ替え可・説明はホーム・作業場は隔離）

残り（実装中に潰す）:
- **引数の数** — 0〜2個に固定するか、増やせるようにするか
- **レールの分類** — じぶん／文／式／変数／数 の並びと、見出しの挟み方
- **既存46問と繋ぐか** — お題にドリルの題材を流用すると同じ題材を2通りで学べる
