# BLOCKS.md — ブロックで組んでから書く（pyblock 設計）

> 第5のアプリ `pyblock.html` の設計。実装前に固めたもの。
> 読みやすい版: https://claude.ai/artifact/2NRJqxpmTcXodPst5b88hV

## 解こうとしている問題

スマホで Python を打つと、**10分かけて書いたコードがエラーになる**。原因が「構造を間違えた」のか
「コロンを忘れた」のか切り分けられない。何が悪かったのか学べないまま疲れだけが残る。

初学者が詰むのは **構造**（何をどう繰り返すか）と **記法**（Python の文字の並べ方）を
**同時に**やらされるから。ブロックで先に構造を確定させれば、残る不確実性は**記法だけ**になる。

## 4つの段

1. **ブロックで組む** — タップだけ。キーボードを出さない
2. **実行して動く** — 成功体験1「構造は正しい」
3. **ブロックを見ながら Python で打つ** — **生成された Python は見せない**
4. **出力がブロック版と一致** — 成功体験2「書けた」

**③で Python を見せてはいけない。** 見せると「文字の書き写し」になり、確定させた構造が使われず
成功体験も薄い。見せるのは**形**だけ:「この形を Python で書くとどう書く？」——確定しているのは構造、
思い出すのは記法。詰まったとき用に「答えを見る」は用意する。採点は**ブロック版の出力との一致**
（記述モードと同じ `PyRun.norm` 比較）。

## 速さが生命線

この企画が成立するかは①が本当に速いかだけで決まる。`for i in range(4):` の中に `if` と `print`:

| | 数 | キーボード |
|---|---|---|
| ブロック | **10タップ**（for 1 + 数字 1 + if 1 + 条件チップ 5 + print 1 + 式チップ 1） | **0回** |
| 手打ち | 41文字＋インデント＋記号 | 必須 |

**最初に検証すべきはここ。** 見た目より先に操作感を出す。

## 2層に分ける

| 層 | 組むもの | やり方 |
|---|---|---|
| **文** | for / if / while / print / 代入 | 新規のブロック（入れ子・タップで挿入） |
| **式** | `i % len(kansu)` / `kansu > 3` | **既存の組み立てドリルのチップ方式を流用** |

式まで入れ子ブロックにすると複雑さが倍になる。式を組む UI は46問のドリルで**もう完成している**。
新規に作るのは「文を縦に積む部分」だけ。

## ブロックカタログ（第1版・14種）

範囲は**辞書がカバーする範囲に揃える**。

| id | ブロックの表示 | 生成される Python |
|---|---|---|
| `assign` | ［変数］に［式］を入れる | `kansu = 5` |
| `addassign` | ［変数］に［式］を足し込む | `kansu += 1` |
| `input` | ［変数］に入力を1行読む | `kansu = input()` |
| `input_int` | ［変数］に入力を数として読む | `kansu = int(input())` |
| `print` | ［式］を表示 | `print(kansu)` |
| `print_end` | ［式］を改行せず表示 | `print(kansu, end='')` |
| `for_range` | ［変数］を0から［数］回くりかえす | `for i in range(4):` |
| `for_in` | ［式］から［変数］を1つずつ | `for x in kansu:` |
| `while` | ［条件］の間くりかえす | `while kansu > 0:` |
| `if` | もし［条件］なら | `if kansu % 2 == 0:` |
| `else` | そうでなければ | `else:` |
| `append` | ［変数］に［式］を足す | `kansu += [x]` |
| `break` | ぬける | `break` |
| `continue` | 次へ飛ばす | `continue` |

**第1版では入れない**: def / import / 辞書 / スライス / try / lambda / 内包表記

## データ構造

```js
[
 {t:'assign', v:'kansu', e:['5']},
 {t:'for_range', v:'i', e:['4'], body:[
    {t:'if', e:['i','%','2','==','0'], body:[
       {t:'print', e:['i']}
    ], orelse:[
       {t:'print', e:["'-'"]}
    ]}
 ]}
]
```

- `v` = 変数名スロット（固定の小集合から選ぶ）
- `e` = 式スロット。**トークン配列**＝既存ドリルと同じ形なので `joinCode()` がそのまま使える
- `body` / `orelse` = 子ブロックの配列

**コード生成**: 木を歩いて1文1行。C字は `:` で終えて `body` を深さ+1 で再帰。
インデントはスペース4つ固定。式の文字列化は既存の `joinCode(e)`。

## 操作モデル（ドラッグは使わない）

スマホで掴んで運ぶ操作は遅く、360px では特に苦しい。**挿入点が常に1つあり、
パレットをタップするとそこに入る。**

- パレットのブロックをタップ → 挿入点に入り、挿入点はその次へ
- C字ブロックを入れたら挿入点は**自動で中に入る**（for を置いた次は中身を書くのが普通）
- ブロックをタップ → 選択。↑ ↓ ⇤ ⇥ 🗑 が出る（移動・字下げ・削除）
- 「外に出る」で挿入点を親の次へ

**キーボードを出さない工夫**
- 変数名: `kansu` `kansu1` `kansu2` `i` `n` `x` の固定パレット（約束4 と一致）
- 数: テンキー＋よく使う値（0 1 2 3 5 10 100）
- 文字列: プリセット（`''` `' '` `'-'` `'OK'`）＋必要なら短い入力
- 演算子: 既存のチップ

## 画面（360px）

段差は**字下げではなく左の色帯**で示す。360px で右に寄せると3段で詰む。

```
×  ブロックで組む
┌───────────────────┐
│ kansu = 5          │
│ for i in range(4): │
│ ▏ if i % 2 == 0 :  │   ← 左の色帯が段差
│ ▏▏ print( i )      │
│ ━━━━━━━━━━         │   ← 挿入点
└───────────────────┘
[文][式][変数][数]          ← パレットのタブ
print for if while ＝ ぬける
▶ 実行        ✎ 自分で打つ  ← 固定アクションバー
```

## verify.py との関係

約束1 をここにも通す。ただし素直にやると**コード生成器が JS と Python の2つ**必要になり、
既知の負債である二重管理がもう1件増える。

**回避策**: データに `blocks` と**生成結果 `code`** と `out` を持たせる。`verify.py` は `code` を
実行して `out` と一致するかだけを見る（既存の検査と同じ形）。
**JS 側の生成器が同じ `code` を吐くかは、アプリ起動時に1回自己テストする。** ズレたら即わかる。

## 障壁

**設計で潰したもの**
- モバイルのドラッグ&ドロップ → 廃止。最大の障壁が消えた
- 式の複雑さ → 既存チップ再利用で実装量が半減
- 横スクロール → 段差を色帯にして解消
- 生成器の二重管理 → データに生成結果＋起動時自己テスト
- 実行基盤 → `PyRun`（Worker・逐次出力・中断）がそのまま使える

**残るもの**
- パレットの物量（14ブロック＋スロット）で画面が窮屈 → タブで分ける
- 式チップの文脈依存（条件用 vs 算術用）→ 最初は全部出す
- 間違った構造も組めてしまう → 実行すればエラーが出る。それは学びなので許容
- 規模。これまでで最大 → 段階的に出す

## 置き場所

`pydrill.html` / `pydrill-pro.html` の中には**入れない**。2枚はすでに120KB超で中身が重複しており、
大きな機能を足すと同じものを2回書くことになる（検証349件の面にも影響）。

`pyplay.html` と同じく**独立した1枚 `pyblock.html`** で作り、育ってから合流を判断する。
ブロックを組むところまでは純粋な JS なので**オフラインで動く**。通信が要るのは実行のときだけ
——約束2 の構造と一致する。
