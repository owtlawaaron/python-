# BLOCKS.md — ブロックで組んでから書く（pyblock 設計）

> 第5のアプリ `pyblock.html`。**骨組みは実装済み**（組む → 実行 → 写経 → 判定 まで通る）。
> 読みやすい版: https://claude.ai/artifact/2NRJqxpmTcXodPst5b88hV

## 解こうとしている問題

スマホで Python を打つと、**10分かけて書いたコードがエラーになる**。原因が「構造を間違えた」のか
「コロンを忘れた」のか切り分けられない。何が悪かったのか学べないまま疲れだけが残る。

初学者が詰むのは **構造**（何をどう繰り返すか）と **記法**（Python の文字の並べ方）を
**同時に**やらされるから。ブロックで先に構造を確定させれば、残る不確実性は**記法だけ**になる。

## 4つの段

1. **ブロックで組む** — タップだけ。キーボードを出さない
2. **実行して動く** — 成功体験1「構造は正しい」
3. **ブロックを見ながら Python で打つ** — **生成された Python は見せない**
4. **出力がブロック版と一致** — 成功体験2「書けた」

**③で Python を見せてはいけない。** 見せると「文字の書き写し」になり、確定させた構造が使われず
成功体験も薄い。見せるのは**形**だけ:「この形を Python で書くとどう書く？」——確定しているのは構造、
思い出すのは記法。詰まったとき用に「答えを見る」は用意する。採点は**ブロック版の出力との一致**
（記述モードと同じ `PyRun.norm` 比較）。

## 速さが生命線

この企画が成立するかは①が本当に速いかだけで決まる。`for i in range(4):` の中に `if` と `print`:

| | 数 | キーボード |
|---|---|---|
| ブロック | **10タップ**（for 1 + 数字 1 + if 1 + 条件チップ 5 + print 1 + 式チップ 1） | **0回** |
| 手打ち | 41文字＋インデント＋記号 | 必須 |

**最初に検証すべきはここ。** 見た目より先に操作感を出す。

**実測（2026-09-17）**: 数は「123 数を書く」でブロックに直接書き込む（キーパッド）。
`1` の札を探す必要が無くなった。任意の数・小数・負数も入る。

**実測（2026-09-15・骨組み）**: `def tasu(a,b) / return a+b / print(tasu(2,3))` が
**14タップ＋関数名の入力1回**。手打ちなら56文字。360px で横スクロールなし。
最初は16タップだったが、`def` の外へ出すのに「行を選ぶ→⇤→スロット」で3タップ使っていたため、
レールに **「⇤ 外へ」**（挿入点を親の次へ出す）を足して14に減らした。

## 2層に分ける

| 層 | 組むもの | やり方 |
|---|---|---|
| **文** | for / if / while / print / 代入 | 新規のブロック（入れ子・タップで挿入） |
| **式** | `i % len(kansu)` / `kansu > 3` | **既存の組み立てドリルのチップ方式を流用** |

式まで入れ子ブロックにすると複雑さが倍になる。式を組む UI は46問のドリルで**もう完成している**。
新規に作るのは「文を縦に積む部分」だけ。

## ブロックカタログ（第1版・14種）

範囲は**辞書がカバーする範囲に揃える**。

| id | ブロックの表示 | 生成される Python |
|---|---|---|
| `assign` | ［変数］に［式］を入れる | `kansu = 5` |
| `addassign` | ［変数］に［式］を足し込む | `kansu += 1` |
| `input` | ［変数］に入力を1行読む | `kansu = input()` |
| `input_int` | ［変数］に入力を数として読む | `kansu = int(input())` |
| `print` | ［式］を表示 | `print(kansu)` |
| `print_end` | ［式］を改行せず表示 | `print(kansu, end='')` |
| `for_range` | ［変数］を0から［数］回くりかえす | `for i in range(4):` |
| `for_in` | ［式］から［変数］を1つずつ | `for x in kansu:` |
| `while` | ［条件］の間くりかえす | `while kansu > 0:` |
| `if` | もし［条件］なら | `if kansu % 2 == 0:` |
| `else` | そうでなければ | `else:` |
| `append` | ［変数］に［式］を足す | `kansu += [x]` |
| `break` | ぬける | `break` |
| `continue` | 次へ飛ばす | `continue` |
| `def` | ［名前］（［引数］）という処理をつくる | `def tasu(a, b):` |
| `return` | ［式］を返す | `return a + b` |
| `call` | ［名前］を呼ぶ | `tasu(2, 3)` |
| `elif` | そうでなくて［条件］なら | `elif kansu > 0:` |
| `pass` | なにもしない | `pass` |
| `raw` | じゆう（1行そのまま書く） | 書いたとおり |

**関数は第1版から入れる。** 名前を付けられることが、自由に作るサンドボックスの手応えを決めるため。

**第1版では入れない**: import / 辞書 / スライス / try / lambda / 内包表記

## データ構造

```js
[
 {t:'def', name:'tasu', args:['a','b'], body:[
    {t:'return', e:['a','+','b']}
 ]},
 {t:'print', e:['tasu','(','2',',','3',')']},
 {t:'assign', v:'kansu', e:['5']},
 {t:'for_range', v:'i', e:['4'], body:[
    {t:'if', e:['i','%','2','==','0'], body:[
       {t:'print', e:['i']}
    ], orelse:[
       {t:'print', e:["'-'"]}
    ]}
 ]}
]
```

- `v` = 変数名スロット（固定の小集合から選ぶ）
- `e` = 式スロット。**トークン配列**＝既存ドリルと同じ形なので `joinCode()` がそのまま使える
- `body` / `orelse` = 子ブロックの配列
- `name` = 関数名。**ここだけキーボードを使う**（`def` のみ）
- `args` = 引数名の配列。固定の小集合から選ぶ（`def` のみ）

**コード生成**: 木を歩いて1文1行。C字は `:` で終えて `body` を深さ+1 で再帰。
インデントはスペース4つ固定。式の文字列化は既存の `joinCode(e)`。

## 操作モデル（タップ＋ドラッグ併用・レールは左）

**2026-09-17 変更**: ドラッグ&ドロップを足した（iPad 対応に伴い）。
ただし**タップ挿入は残す**。速さの生命線であることに加え、**WCAG 2.2 の 2.5.7（ドラッグ操作）は
ドラッグに単一ポインタの代替を必須にしている**ため、タップとキーボード操作は仕様上も必要。

- **レールの札をドラッグ** → 置きたい場所へ。**判定は「レールの外へ出たか」**。
  縦移動で判定してはいけない（レールは縦スクロールする。下部の札を面の上部へ運ぶと
  縦移動の方が大きくなり、実測 dx=182 / dy=367 で横優先の判定は成立しなかった）。
- **行のグリップ（⠿）をドラッグ** → 並べ替え・入れ子への出し入れ。幅は 24px（WCAG 2.5.8 最小）。
- **面の外へ出すと削除**。ドラッグ中は画面下に「はなすと消えます」を出し、ゴーストを赤にする。
- **たな** — 使わないブロックの置き場。ドラッグで預け、タップで挿入点へ戻す。
- ドラッグ直後の click は 400ms 無視する（レール札の tap と二重挿入になるため）。

## 自分で打つ画面の字下げ（2026-09-18）

素の `<textarea>` は改行しても行頭にもどるだけ。**Python はインデントが構造**なので、
ふつうのエディタと同じ振る舞いが無いと「打つ」の練習にならない（依頼主の指摘）。

- `:` で終わる行のあとの Enter → **1段ふかく**
- `return` / `break` / `continue` / `pass` / `raise` の行のあとの Enter → **1段あさく**
- `else:` / `elif ` / `except` / `finally:` を**打ち終えた瞬間**に1段もどす
  （改行のときには「これから何を書くか」が分からないので、ここだけ入力を見る）
- 行頭の空白の Backspace → **4つまとめて**消す
- Tab で字下げ、Shift+Tab でもどす

**Tab をそのまま字下げに使うとキーボードだけの人が閉じ込められる**（WCAG 2.1.2）。
Monaco / CodeMirror が採る作法にそろえて、**Esc を押した直後の Tab だけは抜ける**。
その旨を `#w-help` に常時出す（隠された作法は無いのと同じ）。

## 盤の寄り引き（2026-09-18）

面は「上から積み上げるリスト」のままだが、**2本指でつまんで寄り引きできる盤**にした。
10行を超えたとたん全体が見えなくなるため（じゃんけんは12行で 100% では入らない。
50% にすると12行すべてが1画面に入る）。

- `transform:scale` ではなく **`zoom`** を使う。スクロール量と `getBoundingClientRect` が
  素直に付いてくるので、**ドラッグの当たり判定を書き直さずに済む**（0.7倍でも入れ子判定が通る）。
  入れ子のしきい値だけ `30*ZOOM` にした。
- `.canvas{touch-action:pan-x pan-y}`＝**ページ全体のピンチ拡大を面の上でだけ止める**。
  1本指のスクロールは native のまま。2本指の意味をこちらで決められる。
- PC は Ctrl+ホイール。つまみは Figma / Miro と同じ**右下**（内容は左上から伸びるので
  右下がいちばん字を隠さない）。
- **`::before` で当たり判定を広げてはいけない**。`position:relative` を持たないボタンの
  `::before{inset:-7px}` は絶対配置の親を基準に解決され、**3つとも枠いっぱいに重なって
  いちばん後ろの「＋」が全部を奪う**。34px あれば広げる必要は無い。

### 島（しま）— 実装（2026-09-19）

盤の上にスタックを いくつも置ける。**動くのは「ほんたい」だけ**、ほかは「したがき」で実行されない。
`code()` は `PROG`（ほんたい）しか見ないので、**したがきが実行に混ざらないことは構造上 保証されている**
（実測でも確認: したがきに出した行は生成コードから消える）。

- **何もない盤に落とすと したがきになる。** これまでは面の外＝削除しか無く、
  「間違えたから どかそう」が削除だった（H-15）。Scratch と同じで、
  盤に置くのは「取っておく」で、消すのは面の外へ出したときだけ。
- **「↑ ほんたいへ」** で したがきを本体の末尾へ入れる（ドラッグの代替・WCAG 2.5.7）。
- **つまみ（⠿）で島ごと動かせる。** 位置は `zoom` を割り戻して盤の座標で持つ。
- **からの したがきは 物として残さない**（`pruneIsles()`）。
- 島の幅は中身で決まるので、**作った瞬間に1回だけ** はみ出しを直す（`fitIsle()`）。
  毎回直すと指の下で勝手に動く。
- 保存は盤ぜんたい（`{p, i:[{x,y,b}], m:{x,y}}`）。`is.el`（DOM）は入れない——
  入れると循環参照で `JSON.stringify` が投げる。旧い配列形式も読める。
- 挿入点は どの島にも置ける（`findParentAny` / `roots()`）。
  ただし **`firstHole` / `walkWhy` / `gen` は ほんたい だけ**を見る＝
  したがきが未完成でも実行は止まらない。下書きとはそういう物。

### 無限キャンバスにしなかった理由（2026-09-18）

**位置に意味を持たせない。** Python はインデントが構造なので、ブロックを2次元に自由配置すると
「どれが本体か」「どの順に実行するか」が曖昧になる。Scratch が自由配置でよいのは、
**ハットブロックの下に繋がった物だけが動く**という規則があるから。

次の段階として**島（しま）**を置く: 盤の上に複数のスタックを置け、
**1つが本体（実行される）、他は下書き（実行されない）**。下書きを本体にドラッグするとくっつく。
これは Scratch の規則をそのまま持ってきた形で、インデント構造と矛盾しない。未実装。

## 式バー（2026-09-19）

`print( )` の中をレールの札で埋めるのは**組むには速いが、直すには向かない**。
先頭の変数を間違えたら末尾から4個消して4個入れ直すことになる（審査 H-13）。

**先行例は Excel の数式バー。** セルを押して組んでもいいし、直接打ってもいい。
1985年に同じ問題が解かれている。どちらか一方に寄せないのが答え。

- 式・変数・引数のスロットを選ぶと、道具列の上にバーが出る。
- **バーはフォーカスを奪わない。** 出るだけ。打ちたくなったら触る。
  奪うと毎回キーボードが出て、札で組む流れを壊す。
- Enter か「入れる」で確定。Esc で戻す。外したときも確定する。
- 確定したら `exprWhy()` に通し、壊れていたらバーを赤くしてトーストを出す。
- **打っている最中は上書きしない。** ただし**差し先そのものが変わったら必ず映す**——
  変わっていないのに残った値を書き戻すと、別のスロットへ流し込む事故になる（実際に踏んだ）。

トークン化（`tokenize()`）は `joinCode()` と往復する。実測:

| 入力 | トークン | 戻したもの |
|---|---|---|
| `1 + 2 * 3` | `["1","+","2","*","3"]` | `1 + 2 * 3` |
| `-5` | `["-5"]` | `-5` |
| `3 - -5` | `["3","-","-5"]` | `3 - -5` |
| `gg.key('left')` | `["gg.key","(","'left'",")"]` | `gg.key('left')` |
| `(x - y) % 3 == 2` | 9個 | `(x - y) % 3 == 2` |
| `'閉じ忘れ` | `["'閉じ忘れ'"]` | `'閉じ忘れ'` |

単項マイナスは数とくっつける（キーパッドが作る形にそろえる）。
閉じ忘れたクォートは閉じてやる。

## 分類の色（2026-09-17）

全部が同じ色だと覚えられない。**色を分類の手がかりにする**。ただし色は
**唯一の手がかりにはしない**——印の形と見出しの言葉でも分かれている（WCAG 1.4.1）。

**5色＋中立に絞る**。Scratch は9分類あるが、初心者が覚えられるのは5つ前後。

| 分類 | 何が入るか | 色 | 印 |
|---|---|---|---|
| ながれ | for / while / if / elif / else / break / continue / pass | 橙 `hsl(34,64%,66%)` | ぐるっと回る矢印 |
| だす・いれる | print / print続き / 入力 / 数で入力 | 青緑 `hsl(172,44%,58%)` | 受け皿に下向き矢印 |
| いれもの | ＝入れる / ＋=足す / リストに足す | 青 `hsl(214,62%,70%)` | 角丸の箱に点 |
| かんすう | def / return / 呼ぶだけ / じぶんの関数 | 桃 `hsl(330,58%,71%)` | 右向きの三角 |
| しき | 数 / 計算 / 比べる / 区切り / 変数 / 字 / 道具 | 紫 `hsl(281,66%,66%)` | 分類ごとに別（記号の札には出さない） |
| じゆう | 生の Python 行 / 消す | 中立 `hsl(280,8%,62%)` | 波線 |

実測コントラスト（面 hsl(276,22%,7%) / レール 11% / 地 15%）は
9.63 / 9.11 / 8.13 / 7.69 / 5.93 / 6.74 で、**6色すべてどの地でも 4.5:1 を超える**。
紫だけ `--accent`(L62) より 4% 明るい `--c-expr`(L66) を使う。accent のままだと
地の上で 4.22:1 で AA に届かないため（塗りとしての accent は今まで通り）。

出る場所:

- **レール** — 印の色・見出しの色・押したときの塗り。
- **面の行** — グリップのすぐ右の**4px の帯**と、キーワード（`for` `print` …）の色。
  帯をグリップの直後に置くのは、**深さに関係なく同じ x に来て縦に読める**から。
  字下げの棒は中立色にした——色を持たせると分類の帯と見分けがつかない。
- **たな** — 札の頭の点。
- **設定シート** — 並びの一覧に色チップを出す。ここが**色の凡例**も兼ねる。

分類は `STMT[].c` の1か所で決まる。面の行の色もレールの欄もここから引く。

## 拡大しなくて済むようにする（2026-09-17）

`user-scalable=no` / `maximum-scale=1` は**使わない**。WCAG 1.4.4 違反だし、
iOS Safari は無視する。効くのは別の3つ:

1. **`html{touch-action:manipulation}`** — ダブルタップ拡大を止める。
   タップの多い画面で「連打していたら勝手に拡大した」の本体はこれ。指での拡大は残る。
2. **入力欄を 16px 以上に固定**（`font-size:max(16px,1rem)`）— iOS は
   16px 未満の入力欄にフォーカスすると自動で寄る。
3. **画面の中で文字サイズを変えられる**（小/中/大/特大）— そもそも拡大する理由を消す。
   `%` 指定なので端末側の文字サイズ設定を上書きしない。
   レール幅は `rem`（`6.75rem` / iPad `10.5rem`）にしたので**文字と一緒に伸びる**。

あわせて `body{overscroll-behavior:none}`（引っ張って再読み込みを止める）。

## レールの見た目＝macOS のソースリスト（2026-09-17）

参照: macOS の Sidebar / Source List（`NSOutlineView` のグループ項目、`NSSplitViewController.toggleSidebar(_:)`）。
**踏襲した所**と**踏襲しなかった所**を分けて残す。後から「なぜ真似ていないのか」で迷わないため。

踏襲した:

- **行は左揃えの平たい列**。影も枠も無い。印（15px）＋ラベルの2カラムで、
  `.tx` の左端は全行そろえる（実測 48px の1列）。
- **グループ見出しは行き先ではない**。`pointer-events:none` で押せない。
  `isGroupItem:` が返す非選択の見出しと同じ扱い。
- **見出しは sticky**。ただし節ごとに `.rsec` の箱に入れる。
  箱に入れないと sticky の含みブロックがレール全体になり、**通り過ぎた見出しが上に積み上がる**。
  箱に入れた今は常に1枚だけ貼り付く。
- **畳めるサイドバー**。切替は分割長方形のアイコン（`toggleSidebar(_:)` の標準アイコン）。
  畳んだら `--rail-w:0` に加えて padding も 0・`visibility:hidden` にする。
  opacity だけだと細い帯が残り、**Tab が見えないレールの中を巡る**。

踏襲しなかった:

- **選択の塗り**。ソースリストの選択は「いま居る行き先」を示す。
  レールは行き先ではなく道具箱で、押すと挿入されて終わり、選択は残らない。
  塗りを残すと嘘になるので付けない。押した瞬間だけ `:active` で紫に沈む。
- **半透明（`NSVisualEffectView`）**。`backdrop-filter` は使わない。
  tango で記録済みの通り、親の filter 変更のたび再計算されて古い GPU のスクロールを殺す。
  代わりに**明度差だけ**で材質を分ける（レール `hsl(276,16%,11%)` / 面 `hsl(276,15%,8%)`）。
- **行ごとに違うアイコン**。印は**分類ごとに1種**。
  `+` `<` `[` `'` のように**札そのものが記号の行には印を出さない**（同じ形が2つ並んで読みにくい）。
  桁だけ空けて列は保つ。

足したもの:

- **`.railnow`（レールの先頭に貼り付く1行）** — レールが持つ唯一の本物の状態＝
  **「いま押したらどこに入るか」**。`print の式` / `def の引数` / `2行目に文`。
  見出しの sticky 位置はこの行の**実測高さ**を `--now-h` に入れて合わせる（折り返しても潜らない）。
- **入らない節は薄く**（`.off`, opacity .34）。式の差し先が無いときに `+` を押すと
  トーストが出るだけだったのを、**押す前に分かる**ようにした。
  押せなくはしない——押せば理由がトーストで出る方が学べる。

## 旧: 操作モデル（ドラッグは使わない・レールは左）

スマホで掴んで運ぶ操作は遅く、360px では特に苦しい。**挿入点が常に1つあり、
レールをタップするとそこに入る。**

**レールは左が既定**（作者が左利き。拾う手が左、読む面が右）。
**左右は設定で入れ替えられる**——利き手が変われば親指圏も変わるため。
レールは**縦に弾いて（スワイプして）探す**。分類の見出しが挟まる。つまみを引くと畳めて面を全幅にできる。
レールの札は**短い名前**（`print` `for` `def`）で、**意味はホームで引く**。

- レールのブロックをタップ → 挿入点に入り、挿入点はその次へ
- C字ブロックを入れたら挿入点は**自動で中に入る**（for を置いた次は中身を書くのが普通）
- ブロックをタップ → 選択。↑ ↓ ⇤ ⇥ 🗑 が出る（移動・字下げ・削除）
- 「外に出る」で挿入点を親の次へ
- 自分で作った関数は**レールの「じぶん」欄に並ぶ**。以後タップで呼べる

**キーボードを出さない工夫**
- 変数名: `kansu` `kansu1` `kansu2` `i` `n` `x` の固定パレット（約束4 と一致）
- 数: テンキー＋よく使う値（0 1 2 3 5 10 100）
- 文字列: プリセット（`''` `' '` `'-'` `'OK'`）＋必要なら短い入力
- 演算子: 既存のチップ
- **関数名だけは打つ** — 名前を付けるのは関数ごとに1回で、しかもそれ自体が学習内容。
  トークン1つずつ打つのとは性質が違う

## ホーム・保存・お題（2026-09-19 実装）

BLOCKS.md が「決まった」と書いておいて 未実装だった3つを入れた。タブは **ホーム / 組む / 書く**。
見本もホームに畳んだ（タブを4枚にしない）。ホームの中は4区分。

### 辞書（BDICT・21ブロック / 28例）

**辞書・原子辞書・エラー辞書と同じデータ形**にした（`{cat, items:[{id,sym,d,v:[{l,c,o,i?}]}]}`）。
だから `verify.py` の `check_dict()` が**そのまま流用でき、28例すべてを毎回 実行照合する**。
`verify.py pyblock.html` で走る（`extract()` が `var NAME=` も受けるようにした）。

**入れた初回で自分の書いた出力が1件まちがっていた**——`random.seed(1)` の `randint(1,6)` は
3 ではなく **2**（CPython 3.11 と Pyodide 3.13.2 の両方で一致・再現あり）。
辞書が嘘をつかないことを機械で担保する、という設計がその場で効いた。

各例に「▶ ここで ためす」を付けた。押すとその場で Pyodide が走る。
**辞書に書いてある出力と、実際に走らせた出力を、同じ画面で見比べられる。**

### お題（TASKS・6題・任意）→ 14題・3段に改装（後述「組み立ての大改造」）

`{id,n,d,o,i?,m}`。**`m`（模範解答）を持たせて `check_tasks()` で実行照合する**——
「この出力になるように組め」と言う以上、その出力に**本当に到達できる**ことを機械で確かめる。
解けない問題を出さないための仕掛け。

取ると組み立て画面の上に帯が出て、期待する出力を常時見せる。▶実行 のたびに判定し、
帯が緑（できた）か赤（ちがう）になる。やめるのは帯の「やめる」1タップ。

### のこす（localStorage・名前つき・最大40）

`pyblock.saves` に `{n,t,b}`。ホームの「のこした」に、名前・時刻・1行目の見出しで並ぶ。
タップでもどす（`snap()` を通すので ↺ で取り消せる）、× で消す。
設定シートからも「＋ のこす」で呼べる。

### 直したバグ

- **縦の flex では中身が入りきらないと各項目が縮む。** `overflow-y:auto` を付けても
  縮む方が先に効く。21枚の辞書カードが 44px → **12px** に潰れ、`overflow:hidden` で
  文字ごと消えていた。`.hbody>*{flex:0 0 auto}` で止める。
- **トーストがタップを食っていた。** 下に移したので、出ている1.7秒のあいだ
  真下の道具列と実行ボタンが死んでいた。`pointer-events:none` と、
  退場時の `visibility:hidden`（`transform` で外へ出しただけでは画面内に残って当たり判定を持つ）。

## 組み立ての大改造（2026-09-19）— 見て選ぶ を やめる

依頼主の指摘がそのまま要件だった。

> ブロックを見ながらこうなんだろうなと考えて組み立てるの、学習的にいい効果が有ると確信しました
> なのでそこの問題を増やしたり、**私がブロックを見ることでそれにひきよらさられないように**

**ここが問題の核。** レールに札が全部見えている状態では、解いているのは

「何が要るんだったか」を **想起（recall）** する課題ではない。
選択肢が見えているテストと、白紙に書くテストが別物なのと同じ。
実装は 3つに分けた。

| t10 | 大きい方 | `def` / `return` / 呼び出し |

### 2. 3段のフェーディング（`TNAME=['みほん','穴うめ','白紙']`）

同じ1題を、**足場を外しながら3回**やる。認知負荷理論の
**worked example → completion problem → full problem**（Sweller / Renkl）を、そのまま3段にした。

| 段 | 盤の初期状態 | レール | 何を問うているか |
|---|---|---|---|
| **みほん** | 模範解答が**そのまま組んである** | ふつう | 読む。▶で出力を確かめる |
| **穴うめ** | 組んであるが**式が2つ空** | ふつう | 空いた所だけ埋める |
| **白紙** | **空** | **全欄たたんだ状態** | 名前を思い出して引く |

- **穴を空けるのは「最後の2つ」**（`makeHoles()` が式を持つ札を先頭から集めて末尾から潰す）。
  **backward fading**——先に消すのは**終わりの方**。始まりを残すと、
  「ここまでは合っている」という足場が最後まで効く。
  例 t4 では `goukei += ` と `print()` の2つが空になる。
- **白紙はレールを畳む。** `pref.shut = SORD.slice()` を書いて全欄を閉じる。
  実測で **見えている札 0 / ひらいている欄 0 / コード空**。
  これで初めて「ひきよせられない」状態になる。閉じた欄は手で開けるし、
  **さがす**（下記）で名前から引ける——**閉じ込めではなく、既定値を裏返しただけ**。
- 段は**自動で上がる**。`takeTask(i)` に段を渡さないと `min(2, 済んだ段+1)`。
  カードには3つのボタンが並び、クリア済みに ✓、今やっている段に `now` の印。
  記録は `pref.tdone[id] = 到達した最大の段`（`{"t1":2}` の形）。
- 帯に **ヒント** ボタン。白紙で完全に詰まった時の唯一の出口
  （消えないトーストで出す＝読み終わるまで残る）。

### 3. レールの「さがす」（`RFIND` / `railFilter()`）

白紙でレールを畳んだ以上、**名前から引ける道**が要る。レール最上段に検索欄。

- 打つと、欄の区切りを**全部無視**して「**みつかった N**」の1枚に平す。
  畳んでいようが隠していようが出る（`shut` / `hide` を跨ぐ）。
- 実測：`for` → `for range` `for in` ／ `print` → `print` `print end`。
  そこから挿すところまで通した。
- × で戻る。`data-fk="rfind"` を付けてあるので `render()` を跨いで**焦点が残る**。

**この3つが噛み合って初めて成立する。** 畳むだけなら不便になっただけ、
検索だけなら見えているのと変わらない、題が少なければ3段やる意味がない。

### ブロック木を正本にした（`TASKS[].b`）

模範解答を**文字列で持たない**。`b:function(){return [ ...ブロック木... ];}` を持ち、

- **みほん / 穴うめ** はその木をそのまま盤に置く（`cloneBlocks()` で毎回 複製）
- **`m`（期待する模範コード）** は、`scripts` 側で**同じ木から生成**した
- `verify.py` の `check_tasks()` が **`m` を実際に走らせて出力 `o` と照合**する
- ブラウザ側で **`code(b) === m` を14題すべてで確認済み**

つまり *置かれるブロック* と *模範コード* と *期待出力* の三者が、**1つの木から出ている**。
どれか1つを直せば残り2つが自動でついてくるし、ズレたら機械が落ちる。

`verify.py` には `strip_fns()` を足した（`"b":function(){return [...];}` を落として
TASKS を JSON として読む）。`pyblock.html` の照合は **28 → 42件**。

## verify.py との関係

サンドボックスは自由なので検証対象が無い。**検証面は「ホームのブロック辞書」が担う**——
各ブロックの例プログラムを、既存の3辞書と同じ形で実行照合する。

素直にやると**コード生成器が JS と Python の2つ**必要になり、既知の負債である二重管理がもう1件増える。

**回避策**: データに `blocks` と**生成結果 `code`** と `out` を持たせる。`verify.py` は `code` を
実行して `out` と一致するかだけを見る（既存の検査と同じ形）。
**JS 側の生成器が同じ `code` を吐くかは、アプリ起動時に1回自己テストする。** ズレたら即わかる。

## 障壁

**設計で潰したもの**
- モバイルのドラッグ&ドロップ → 廃止。最大の障壁が消えた
- 式の複雑さ → 既存チップ再利用で実装量が半減
- 横スクロール → 段差を色帯にして解消
- 生成器の二重管理 → データに生成結果＋起動時自己テスト
- 実行基盤 → `PyRun`（Worker・逐次出力・中断）がそのまま使える

**残るもの**
- パレットの物量（14ブロック＋スロット）で画面が窮屈 → タブで分ける
- 式チップの文脈依存（条件用 vs 算術用）→ 最初は全部出す
- 間違った構造も組めてしまう → 実行すればエラーが出る。それは学びなので許容
- **面の幅** — 360px からレール96px を引くと面は約250px。長い式は横スクロールか省略になる。
  **試作で最初に見るべき点**
- **関数のスコープ** — 引数と外の変数の区別は初学者の壁。第1版は引数を固定小集合にして踏み込まない
- 規模。これまでで最大 → 段階的に出す
